## Goal

Detect price changes during nightly scrapes, create notifications for users who saved those listings, and build the notification bell + notifications page UI.

## Tasks

### Task 1: Price change detector module with tests

**Files:** `services/scraper/price-change-detector.ts`, `services/scraper/__tests__/price-change-detector.test.ts`

Create `price-change-detector.ts` with two functions:

`detectPriceChanges(supabase, rows)`: Compare scraped listings against current DB prices. Call BEFORE upsert. Fetch current prices for matching `external_id`s, build lookup map, return array of `PriceChange` objects with `listing_id`, `old_price`, `new_price`, `address`.

`createPriceChangeNotifications(supabase, changes)`: For each changed listing, find users who saved it via `saved_listings` join, bulk-insert notifications with `type: 'price_change'` and JSONB payload containing `old_price`, `new_price`, `listing_address`.

Tests (mocked Supabase):
- Returns empty when no priced rows
- Returns empty when no existing listings match
- Detects price increase and decrease
- Ignores same-price and null-rent listings
- Creates notifications per saved user
- Handles listings with no saves gracefully

### Task 2: Integrate price detection into scraper run.ts

**Files:** `services/scraper/run.ts`

Import `detectPriceChanges` and `createPriceChangeNotifications`. In the per-scraper loop:
1. BEFORE upsert: `const priceChanges = await detectPriceChanges(supabase, rows)`
2. Run upsert as normal
3. AFTER upsert: `const notifCount = await createPriceChangeNotifications(supabase, priceChanges)`
4. Log count to metrics output

### Task 3: NotificationBell + Notifications page

**Files:** `apps/web/components/notification-bell.tsx`, `apps/web/app/(campus)/[campusSlug]/notifications/page.tsx`

NotificationBell (client component):
- Props: `userId`, `campusSlug`, `initialUnreadCount`
- Bell SVG icon with red badge showing unread count (hidden when 0)
- Supabase Realtime subscription on `notifications` table filtered by `user_id=eq.${userId}`
- Increment count on INSERT event, cleanup channel on unmount
- Clicking navigates to `/${campusSlug}/notifications`

Notifications page (server component):
- Fetch notifications with LEFT JOIN to listings for address/photo data
- Group by date (Today, Yesterday, This Week, Earlier)
- Each card: listing thumbnail, address (linked), color-coded price change (green arrow down / red arrow up), old->new price with strikethrough, relative timestamp, unread blue dot
- On page load: mark all unread notifications as read via server-side UPDATE
- Empty state: "No notifications yet. Save some listings to get price alerts!"

### Task 4: Add bell to nav + unread count prop threading

**Files:** `apps/web/components/auth-nav.tsx`, `apps/web/components/mobile-nav.tsx`, `apps/web/app/(campus)/[campusSlug]/layout.tsx`

In campus `layout.tsx`:
- Query unread notification count: `SELECT COUNT(*) FROM notifications WHERE user_id = ? AND is_read = false`
- Pass `unreadNotificationCount` to AuthNav and MobileNav

In `auth-nav.tsx`: Render NotificationBell component in authenticated branch.

In `mobile-nav.tsx`: Add "Notifications" link with inline badge count.

- Price detection must run BEFORE upsert or old prices are lost
