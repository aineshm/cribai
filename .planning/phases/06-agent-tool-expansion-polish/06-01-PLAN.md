    1. Create migration `010_chat_conversations.sql`:
       - `conversations` table: id (uuid PK), user_id (FK auth.users ON DELETE CASCADE), campus_id (FK campus_configs), title (text, default 'New Conversation'), last_message_preview (text, nullable, first 100 chars of last message), created_at (timestamptz), updated_at (timestamptz)
       - `messages` table: id (uuid PK), conversation_id (FK conversations ON DELETE CASCADE), role (text CHECK IN 'user','assistant'), blocks (jsonb NOT NULL DEFAULT '[]'), created_at (timestamptz)
       - Indexes: conversations(user_id, updated_at DESC), messages(conversation_id, created_at ASC)
       - RLS on both tables: auth.uid() = user_id pattern (same as saved_listings). Enable RLS. Policies for SELECT, INSERT, UPDATE, DELETE scoped to own user_id. For messages, join through conversations to check user_id ownership.
       - updated_at trigger on conversations (reuse pattern from Phase 3 listings trigger or create new)

    2. Add Conversation and ConversationMessage types to `packages/types/src/chat.ts`:
       ```typescript
       export const conversationSchema = z.object({
         id: z.string().uuid(),
         title: z.string(),
         lastMessagePreview: z.string().nullable(),
         createdAt: z.string(),
         updatedAt: z.string(),
       });
       export type Conversation = z.infer<typeof conversationSchema>;
       ```

    6. Create `POST /api/conversations/[id]/messages` - save a message (role + blocks as JSON). Also update conversation's updated_at and last_message_preview (first 100 chars of text content from blocks). Return { id }.
