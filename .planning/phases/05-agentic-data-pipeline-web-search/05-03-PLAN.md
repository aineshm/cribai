    In `packages/ai/src/tools/handlers/web-search.ts`, add and export `persistWebListing`:
    - Accepts: `{ address: string, sourceUrl: string, rentMonthly?: number, bedrooms?: number, content: string }` and `ToolContext`
    - Uses `context.supabase` to upsert into `listings` table:
      ```typescript
      const { data, error } = await context.supabase
        .from('listings')
        .upsert({
          address: params.address,
          source: 'web_search',
          source_url: params.sourceUrl,
          rent_monthly: params.rentMonthly ?? null,
          bedrooms: params.bedrooms ?? null,
          campus_id: context.campusId,
          is_active: true,
          raw_data: { web_content: params.content },
        }, { onConflict: 'source,source_url' })
        .select('id')
        .single();
      ```
    - After successful upsert, trigger embedding by setting `last_embedded_at` to null:
      ```typescript
      await context.supabase
        .from('listings')
        .update({ last_embedded_at: null })
        .eq('id', data.id);
      ```
    - Return the new listing UUID on success, null on any error
    - Handle errors gracefully -- log with console.error but never throw

    - Calls `persistWebListing` from `@campusnest/ai` with a service-role supabase client and the provided params

    - This API route is what the chat UI calls when a user clicks save/heart on a web-sourced listing that doesn't have a real listing ID yet. The chat UI should:

      2. Receive the real listing UUID back
      3. Then insert into `saved_listings` with that UUID (existing HeartButton flow)
