<objective>
Add a web_search tool to CribAI so it can research live rental listings from the web when the local corpus is insufficient.

Purpose: This is THE core differentiator -- CribAI does what a human agent does: when it cannot find enough in its database, it searches the web on behalf of the student. The "wow moment" is CribAI saying "I couldn't find enough in our database, so I searched the web and found these options."

Output: Working web_search Gemini function-calling tool with Tavily API integration, session caching, and search_listings unique property count hint for auto-triggering.
</objective>

    - getCachedResults: Given query searched <30min ago, returns cached results
    - getCachedResults: Given query searched >30min ago, returns null (expired)

    - setCachedResults: Normalizes query to lowercase trimmed before storing

       - `setCachedResults(query: string, results: WebSearchResult[]): void` -- stores with timestamp, normalizes key to lowercase trimmed

       - Input schema: `{ query: z.string(), location: z.string().optional() }`
       - Check TAVILY_API_KEY env var -- if missing, return graceful message (not throw)
       - Check cache first via `getCachedResults(searchQuery)` -- if hit, use cached results
       - Build search query: `"${query} apartments rentals near ${location ?? 'Madison WI'}"`
       - Call `tvly.search(searchQuery, { maxResults: 8, searchDepth: 'basic', topic: 'general' })`
       - Map results to WebSearchResult array
       - Store in cache via `setCachedResults(searchQuery, webResults)`
       - Build modelContext: numbered list of title + URL + content snippet (first 200 chars)
       - Build clientBlock as type 'text' with formatted results summary (web results are ephemeral, not listing cards -- Gemini presents them conversationally). Per user decision: web results use same ListingCard, but since web results lack UUID ids and structured fields, the handler returns text for Gemini to reason over and present. The ListingCard integration for web results that CAN be structured will be handled in Plan 03.
       - Wrap entire handler in try/catch -- on Tavily error (429, network), return graceful failure message
