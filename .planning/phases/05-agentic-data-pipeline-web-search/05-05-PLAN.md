    Add sessionStorage-based persistence so chat survives navigation (mount/unmount cycles). This is the quick-win approach per the debug diagnosis — database persistence is deferred to Phase 6.

    1. Define a storage key constant: `const CHAT_STORAGE_KEY = 'cribai-chat-messages';`

    2. Create a helper to load messages from sessionStorage on initial render:
       ```typescript
       function loadMessages(): readonly Message[] {
         if (typeof window === 'undefined') return [];
         try {
           const stored = sessionStorage.getItem(CHAT_STORAGE_KEY);
           if (!stored) return [];
           const parsed = JSON.parse(stored) as Message[];
           // Filter out any tool_loading blocks that were in-flight when navigated away
           return parsed.map(m => ({
             ...m,
             blocks: m.blocks.filter(b => b.type !== 'tool_loading'),
           }));
         } catch {
           return [];
         }
       }
       ```

    3. Change useState initializer from `useState<readonly Message[]>([])` to `useState<readonly Message[]>(loadMessages)` (lazy initializer — only runs on mount).

    4. Add a useEffect that persists messages to sessionStorage whenever they change:
       ```typescript
       useEffect(() => {
         try {
           sessionStorage.setItem(CHAT_STORAGE_KEY, JSON.stringify(messages));
         } catch {
           // sessionStorage full or unavailable — degrade gracefully
         }
       }, [messages]);
       ```

    5. Place the persistence effect AFTER the existing cleanup effect (line 46-50) but BEFORE scrollToBottom.

    Important: Do NOT change the Message interface, SSE handling, or any other chat logic. Only add persistence layer. The `tool_loading` filter in loadMessages prevents stale "Searching..." indicators from appearing on restore.
