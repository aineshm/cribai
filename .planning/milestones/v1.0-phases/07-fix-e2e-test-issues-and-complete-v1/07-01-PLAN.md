**CribAI API route (dev auth fix):**
1. Import dev auth utilities at top: `import { isDevAuthEnabled, getDevUserById, DEFAULT_DEV_USER, DEV_USER_COOKIE } from '../../../lib/dev-auth';`
2. Import `cookies` from `next/headers`.
3. After the existing auth header check block (line 162, after the `if (authHeader)` block closes), add dev auth fallback:
```typescript
if (!userId && isDevAuthEnabled()) {
  const cookieStore = await cookies();
  const selectedId = cookieStore.get(DEV_USER_COOKIE)?.value;
  const devUser = selectedId ? getDevUserById(selectedId) : DEFAULT_DEV_USER;
  userId = devUser?.id ?? DEFAULT_DEV_USER.id;
}
```
This follows the exact pattern from `/api/conversations/route.ts` lines 17-21. This fix resolves Bug 3 (schedule_tour dev auth — ToolContext.userId now populated).

**Frontend conversation persistence (Bug 2 fix):**
The CONTEXT.md states: "frontend never calls `/api/conversations` POST endpoint." The `/api/conversations` POST endpoint exists but `cribai-chat.tsx` never calls it, so conversations are never persisted to the database.

In `apps/web/components/chat/cribai-chat.tsx`:
1. Find where the first user message is sent (the send/submit handler).
2. Add logic to call `POST /api/conversations` on the FIRST message of a new conversation (when there is no existing `conversationId`). This should:
   - POST to `/api/conversations` with `{ title: firstMessageText.slice(0, 100) }` (or similar)
   - Store the returned `conversationId` in component state
   - Pass the `conversationId` to subsequent API calls so messages are associated with the conversation
3. If a `conversationId` already exists (user resumed an existing conversation from sidebar), skip the POST and use the existing ID.
4. This follows the lazy creation pattern designed in Phase 6 (06-01 decision): create conversation record on first message, not on chat open.

This wiring, combined with the dev auth fix above (userId now resolved), ensures conversations are persisted to the DB and survive page reloads.

```sql
-- Remove places.googleapis.com URLs from photo_urls arrays
-- These are legacy URLs from the removed GooglePlacesScraper that return 403
UPDATE listings
SET photo_urls = (
  SELECT COALESCE(
    array_agg(url ORDER BY ordinality),
    ARRAY[]::text[]
  )
  FROM unnest(photo_urls) WITH ORDINALITY AS t(url, ordinality)
  WHERE url NOT LIKE '%places.googleapis.com%'
)
WHERE EXISTS (
  SELECT 1 FROM unnest(photo_urls) AS url
  WHERE url LIKE '%places.googleapis.com%'
);
```
